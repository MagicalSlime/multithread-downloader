# 多线程下载器

把文件切成多段并发拉取、绕过服务器对单连接的限速。支持**多任务队列**、**断点续传**、
**全局限速**、**失败自动重试**、**自定义请求头**，服务端不支持分片时自动回退单线程。

界面是网页（HTML/CSS/JS），用系统自带的 WebView2 渲染。

## 运行

```bash
pip install requests pywebview
python main.py
```

Python 3.10+。Windows 上依赖系统自带的 **WebView2 运行时**（Win11 自带；Win10 一般随
Edge 装好了）。下载逻辑部分只需要 `requests`，`pywebview` 只在开界面时用。

| 操作 | 说明 |
|---|---|
| 全部开始 / 全部暂停 | 批量控制列表里的所有任务 |
| 清除已完成 | 把已完成/已取消/失败的任务从列表移走（不影响文件） |
| 同时下载 | 并发任务上限，超出部分自动排队 |
| 限速 | 全局总带宽上限，所有任务共享同一个令牌桶 |

「取消」和「暂停」的区别在于它多问一句：临时文件是删掉还是留着。取消后进度条归零，
方便直接开始下一个任务。失败原因行内显示 + 红色日志，不弹模态框（排队时多个任务同时
失败会弹到手软）。

## 它是怎么提速的

对同一个文件发多个带 `Range` 头的请求，每个线程只负责一段字节区间，各自写入同一个
文件的对应偏移。

**前提**：只有当「单连接被服务器限速」且「你的带宽还有富余」时，多线程才会快。
如果出口带宽本身就跑满了，多开连接不会带来任何提升。用 `tests/bench_live.py` 可以在
自己的网络上实测加速比（只跑固定时长就取消，不会把整个文件拉下来）。

作者实测过一次：1/4/8/16 线程全部稳定在 12.1 MB/s——因为那台机器的出口带宽上限就是
~12.3 MB/s（用两个不同镜像同时下载，总量仍是 12.3 MB/s），单连接早已跑满。

其他几件事也顺带解决了：

- **每线程一个文件句柄，顺序写**。共享句柄 + `seek()` 的 seek 和 write 不是原子操作，
  必须加全局锁，等于把磁盘 I/O 串行化；而 Windows 上没有 `os.pwrite` 可以替代。
- **重试从断点继续**。分片中途断线时，重试请求的是「从当前位置到分片末尾」，
  而不是重发整段。
- **强制 `Accept-Encoding: identity`**。否则服务器压缩后，进度会按解压后的字节数算，
  出现超过 100% 的怪现象。

### 默认 User-Agent 为什么不是浏览器

实测清华 TUNA 镜像站对同一个 ISO 的响应：

| User-Agent | 响应 |
|---|---|
| Chrome 浏览器标识 | **403** |
| `python-requests/2.32.5` | **403** |
| `MultiThreadDownloader/1.0` | 206 |
| `Mozilla/5.0 (compatible; MultiThreadDownloader/1.0)` | 206 |

被拦的原因就是 UA 本身，跟有没有 `Range` 头无关。很多下载工具默认带浏览器 UA，在这些
镜像站上会直接吃 403。遇到要求真实浏览器 UA 的站点，在「高级设置」里改。

## 断点续传怎么保证不写坏文件

数据写在 `<目标文件>.part`，进度记在 `<目标文件>.part.json`。状态文件用
「写临时文件 → fsync → 原子改名」更新，不会出现半截 JSON。

命中以下任何一条就丢弃旧进度重下（并在日志里说明原因）：链接变了、临时文件不存在或
大小对不上、服务器上的文件大小变了、ETag 或 Last-Modified 变了、分片记录没有恰好覆盖
整个文件、服务器这次不支持 Range。

**改了线程数也能续传**：旧的已完成区间会重新映射到新分片上。这里只认「从新分片起点
开始连续覆盖」的部分——各分片进度不一致时，旧区间在新分片里可能是「两段、中间有洞」，
简单求和会把空洞当成已下载，产出残缺文件。

## 设置

偏好设置存在 `%APPDATA%\MultiThreadDownloader\settings.json`，退出时写入、启动时恢复。

**Cookie 刻意不持久化**。它是登录凭据，明文落盘风险太大。

## 测试

```bash
python tests/smoke_test.py    # 核心下载逻辑（23 项，无界面）
python tests/webui_test.py    # 界面桥接 + 真实窗口渲染（11 项）
python tests/bench_live.py    # 真实网络加速比实测（需要外网）
python tests/preview.py       # 离屏生成界面预览图（不截屏）
```

界面换成网页后，逻辑全在 `Bridge` 里，**不开窗口也能完整验证**——绝大多数用例直接对
Bridge 断言，只有最后一项真正拉起 WebView2 确认页面能加载、任务能渲染。

**`preview.py` 不做截屏**：它把 `index.html` 读进来、注入一段假数据，交给无头 Edge
在离屏环境渲染出图。用的是同一份 HTML/CSS/JS，所以预览图和真实界面一致；而且全程
不读屏幕内容，不需要保证窗口在最前，也不会拍到别的东西。

## 已知限制

- **不做哈希校验**。只对比 ETag / Last-Modified 判断资源是否变化。
- **掉电最多丢失最后一个 64 KiB 块**。无缓冲顺序写，偏移单调递增，最坏情况只是小范围
  重下，不会损坏文件。
- **登录态失效不会被识别**。有些站点 Cookie 过期后返回 200 + 一个 HTML 登录页，
  结果会得到一个 HTML 文件。
- **长度未知（无 Content-Length）的资源不能续传**，会退化成单线程流式。
- **代理走环境变量**，界面里没有单独设置项。

## 代码结构

```
main.py                  入口
downloader/
  config.py              DownloadConfig（单次下载）+ AppSettings（偏好持久化）
  util.py                文件名解析/清洗、格式化、Content-Range 解析（纯函数）
  state.py               续传状态的读写与失效校验、分片代数
  core.py                DownloadTask 单任务下载 + RateLimiter 令牌桶
  manager.py             DownloadManager 多任务调度：并发上限、排队、全局限速
  webui.py               pywebview 窗口 + 暴露给 JS 的 Bridge
web/                     界面（真正的 HTML/CSS/JS）
  index.html             结构
  style.css              样式：圆角、阴影、过渡动画
  app.js                 渲染与交互
tests/
  range_server.py        支持 Range 的本地测试服务器 + 坏服务器模拟
  smoke_test.py          核心逻辑测试
  webui_test.py          界面桥接测试 + 真实窗口渲染
  preview.py             离屏预览图
  bench_live.py          真实网络加速比实测
```

依赖方向单向：`webui → manager → core → state → util`。**`core` / `manager` / `state` /
`util` 不依赖任何 UI 库**——这是从 tkinter 换成网页时下载逻辑一行没改的原因。

界面与 Python 之间只有两条通道，都由 JS 主动拉：`snapshot()` 取高频数值（每 100ms），
`drain_events()` 取离散事件。**Python 侧永远不从工作线程往界面推东西**，省掉一整类
线程安全问题。

### 改动时容易踩的坑

都是实际写出来才发现的，记在这里免得重蹈覆辙：

- **调度是异步的**。`start_task` 只是把「想跑」标记挂上，真正启动要等调度线程下一轮；
  `pause_task` 会同步改状态，但线程收尾、状态落盘、事件投递都要晚一步。任何依赖副作用
  的断言都必须轮询等待，不能假定调用返回时就生效——测试里一开始就栽在这上面。
- **`TaskState.RUNNING` 必须真的被赋值**。曾经整份代码里只有读、没有写，任务从探测开始
  就一直停在 PROBING。
- **暂停不是终态**。终态只有 DONE / FAILED / CANCELLED；把 PAUSED 也当终态的话，暂停后
  点取消会被幂等保护挡掉。
- **「用户希望它跑」和「刚点了开始」要分成两个标志**。调度器见到终态会自动摘掉前者
  （防止任务一结束就被反复拉起来），但那样会把用户刚设的也擦掉，导致取消过的任务再也
  无法重启。
- **速度必须在数据停下的瞬间就报 0**，不能交给滑动窗口去算。旧样本会一个个老化出窗口
  而分母不变，读数就拖着一条长尾慢慢降，看起来像「下载还在慢慢停」。
- **进度条的滚动模式必须双向切换**。只在 `total > 0` 的分支里停的话，「长度未知 + 任务
  结束」正好落进缝隙，动画会一直空转——探测失败就是这种情况。
- **界面里用的特殊符号要先确认字体真的有这个字**。实测微软雅黑**不含** ☑(U+2611)、
  ☐(U+2610)、✓(U+2713)，渲染出来和缺字豆腐块像素级完全相同；■/□ 属于 GBK，到处都有。
- **Tk 的 Canvas 只在 macOS 上有抗锯齿**，这也是当初换掉 tkinter 的原因之一：Windows 上
  圆角永远带锯齿，而且没有阴影、渐变、过渡动画可用。
